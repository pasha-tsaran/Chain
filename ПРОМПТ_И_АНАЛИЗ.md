# Рабочее задание для разработки

Создай законченное локальное приложение для браузера на Windows, которое по теме и пожеланиям пользователя готовит русскоязычную статью для Дзена и 1–2 тематические картинки. Реализуй последовательную цепочку из четырёх этапов: анализ задания, подбор инструментов, генерация, проверка и точечная доработка. Каждое звено передаёт следующему структурированный результат. Сохраняй черновики, версии, отчёты и иллюстрации. Покажи этапы и ошибки в интерфейсе.

Автор пишет конкретно, с разным ритмом, без канцелярита, пустых вводных и выдуманного личного опыта. Оформление выбирается по смыслу: связные абзацы, жирный акцент, курсив, действия списком, таблица для сравнения. Автоматическая подача меняется между статьями. Не выдумывай исследования, даты и ссылки. При недостатке материалов обозначай необходимость проверки фактов.

После генерации проведи литературное ревью, затем внешнюю проверку на ИИ. Используй настоящий результат детектора; не подменяй его оценкой языковой модели или эвристикой. При оценке выше 10% меняй только точные выделенные фрагменты. Остальной текст должен сохраниться посимвольно. После правки нужен новый отчёт, связанный с новой версией. Ограничь число итераций и честно показывай непройденный порог, отсутствие подсветки, недоступность сервиса и ошибки.

Найди бесплатный сайт проверки. Подключи автоматическую работу через публичную форму сайта в локальном изолированном браузере; если форма недоступна, предложи перенос отчёта вручную. Отдельно предусмотрен официальный платный API. Не обходи CAPTCHA и ограничения сервиса. Не обещай гарантированного процента и не выдавай машинный текст за доказанно человеческий.

Приложение должно запускаться понятным файлом, сохранять данные локально и экспортировать ZIP с HTML, Markdown, картинками и отчётом. Проверь настоящий запуск на установленной модели, генерацию картинок, точечные замены, защиту от устаревших отчётов, цикл повторных проверок и экспорт. Подготовь документацию, включая ограничения локального запуска. Не отправляй статьи в Дзен автоматически.

## Анализ задания

1. **Роль и результат определены:** приложение для автора канала, результат — публикационный пакет. Браузер выбран пользователем.
2. **Цепочка реализуема:** небольшие отдельные запросы анализатору, автору и редактору; выбор сервисов выполняет код. Модель не придумывает адреса инструментов и не исполняет команды.
3. **Проверяемые критерии:** 1–2 настоящих PNG, сохранённые версии, неизменность текста вне выделений, повторный отчёт после правок, остановка по лимиту, отсутствие выдуманного процента.
4. **Неопределённость снята:** «качественный человеческий текст» преобразован в литературные правила, проверку редактором и возможность ручной редакции. Детектор не заменяет оценку качества.
5. **Граница автоматизации определена:** бесплатный ZeroGPT в браузере и платный Business API — разные способы доступа. Бесплатный режим использует публичную форму через Playwright и зависит от доступности сайта. Ручной перенос служит резервом при CAPTCHA, лимите или изменении интерфейса; ошибку не засчитываем как 0%.
6. **Факты отделены от стиля:** редактор может отметить неподтверждённое утверждение, но без источников не может доказать его истинность. Предусмотрено поле для материалов; ссылки сами по себе не загружаются.
7. **Границы гарантии:** никакая модель или цепочка не гарантирует ≤10% на произвольной теме. Критерий ≤10% обозначает только результат выбранного сервиса для конкретной версии.
8. **Потребление памяти ограничено:** текстовая модель выгружается до запуска модели изображений. Процесс изображений завершается и освобождает видеопамять.
9. **Описания картинок проверяются:** SD-Turbo получает английские описания сцен. Если аналитик вернул русский текст, отдельное звено готовит английский вариант; некорректный ответ останавливает генерацию, а не подменяет картинки случайными.

## Что реализовано из урока

Изучены текстовые разделы урока «VPf05. Цепочки запросов (Chains)», включая пример Python-цепочки и домашнее задание. Видео отдельно не просматривались.

В уроке результат анализа становится входом следующего звена, каждый запрос решает ограниченную задачу, а после генерации выполняется ревью и исправление. Эти принципы перенесены в `workflow.py` и версионируемые шаблоны `prompts.py`. Используется явная цепочка на Python без LangChain: условие урока допускает другой инструмент, а здесь не нужны дополнительные зависимости для оркестрации.

1. **Анализ:** ракурс, потребность читателя, план, ограничения фактов, описания иллюстраций.
2. **Подбор инструментов:** локальная модель Ollama, SD-Turbo или WebUI, режим детектора, формат подачи. Выбор записывается в статью.
3. **Реализация:** статья из блоков Markdown, литературная редактура отдельных цитат, картинки по сценам из плана.
4. **Проверка:** объём, замечания о фактах, внешний отчёт, ограниченный цикл точечных правок и повторная проверка.

Применён навык `stop-slop`: его идеи адаптированы к русскому тексту в промптах. Жёсткие англоязычные запреты не используются как механический измеритель авторства.
